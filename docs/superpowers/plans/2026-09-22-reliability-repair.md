# Purchase workflow reliability repair

Goal: make the advertised purchase-assistance paths executable, traceable and safe to review, with explicit limits on externally dependent capabilities.

The repair specification is the reproducible failures in the audit: stale verified tax values, generic formulas used as jurisdiction rules, public feedback writes, conflicting budget disclosure instructions, invalid dossiers accepted, installation-relative resource failures, nonpersistent inbox state and a model evaluation that never invokes a model.

The implementation keeps separate responsibilities. The tax module owns financial rules and their dated evidence. Dossier generation owns monetary and source consistency. The workflow module owns constrained outbound composition and idempotent inbox state. Repository tools own private path proof, generated fixtures, installation and acceptance checks.

Constraints: preserve the pinned guard submodules; no copied guard implementations or public DATA fallback; public examples are generated synthetic records; model calls follow llmcall defaults; external dealer communications require user authorization. No test result is evidence of a real purchase outcome.

- [x] Private runtime paths: delegate discovery to guards, verify GitHub PRIVATE visibility, reject uninitialized writes, public directories, traversal and link escapes. Wire every live writer to the same API.
- [x] Tax: reproduce failures, use Decimal money, implement supported state mechanisms and real trade/payoff settlement, annotate field evidence, refuse unknown applicability, exercise installed junction paths.
- [x] Dossier: distinguish generated demos from private live input; validate totals, complete comparable quotes, dated local source artifacts and hashes; escape text; verify fresh PDFs without local-path headers.
- [x] Negotiation and inbox: distinguish internal ceiling from authorized offer; compose from approved fields; durable message identities, atomic state, no replay of uncertain draft operations.
- [x] Fixtures and examples: deterministic recipes and reproduction checks, including synthetic routing, quotes, tax cases and dossier configs.
- [x] Installation: idempotent registration of all skill directories and dependency checks without overwriting unrelated user skills.
- [x] Documentation: match actual behavior, remove unsupported savings and timing promises, establish private working directories before any capture.
- [x] Acceptance: run functional CI commands, privacy/style checks, installed-path smoke, PDF visual checks, public inventory smoke and attributable model evaluation. Record unavailable external outcomes explicitly.

Tests are added against each reproduced failure before its production correction. Integration reviews use final code and fresh outputs, with uncertain execution retained as uncertain rather than retried implicitly.

External acceptance is bounded: model cases are synthetic; inventory results retain per-page limitations. Live dealer communications, scheduler deployment and purchase savings are not asserted.
